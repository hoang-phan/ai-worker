# ai-worker-ui

Scope: `app/controllers/**`, `app/views/**`, `config/routes.rb`. Read `app/models/*.rb` only for attribute/validation/enum names when building forms — do not modify models here (that's `ai-worker-domain`'s scope) and do not touch `app/jobs`/`app/services` (that's `ai-worker-orchestration`'s scope).

## File map (the whole scope)

- `config/routes.rb` — `resources :projects` (plus member routes `sync_slack` / `brainstorm` mapped to `project_slack_syncs#create` / `project_brainstorms#create`) nests `jira_syncs` and `bugsnag_syncs` (no index/show; member `run`) and `workflows` (no index; member actions for start, run a runbook stage, clone, advance, resume, roll back to review, delete an image). `stages` nest under a workflow (new/create/edit/update/destroy). Top level: `prompt_templates`, singular `resource :settings`, `root "projects#index"`, Sidekiq Web at `/sidekiq`, health check.
- Projects: `projects_controller.rb` (CRUD only), `project_slack_syncs_controller.rb` and `project_brainstorms_controller.rb` (single `create` each, the "run now" buttons; routed as member `sync_slack` / `brainstorm` so the helper names stay); `app/views/projects/{index,show,new,edit,_form}`, form sections in `projects/form/*` (`_jira`, `_uat_test`, `_ci_loop`, `_local_test`, `_brainstorm`, `_slack`, `_errors`). `show` is the dashboard: one `_workflow_row` per workflow plus `_jira_syncs`, `_bugsnag_syncs`, `_brainstorm`, `_slack_reviews` sections, each with a "run now" button; the time-log checkboxes sit in a `data-controller="select-all"` table. Password fields are never pre-filled (blank keeps the saved value). Helper: `WorkflowsHelper` (`workflow_kind_badges`, `workflow_logged_time_badge`, `time_log_checkbox_data`, `jira_synced_phrase`).
- Workflows: `workflows_controller.rb` (CRUD only), plus one small controller per member-action group, each `include ProjectScoped` + `WorkflowScoped` (shared `set_workflow`): `workflow_transitions_controller.rb` (start, resume, rollback_to_review), `workflow_runbooks_controller.rb` (run_stage, advance, clone), `workflow_positions_controller.rb` (move) and `workflow_images_controller.rb` (destroy_image) — routed with `to: "workflow_transitions#start"` etc. inside the workflows `member` block so the helper names (`start_project_workflow_path`, `image_project_workflow_path`, ...) stay; and `workflow_time_logs_controller.rb` (the project-level batch `log_time` POST routed from the workflows collection); `app/views/workflows/{show,new,edit,_form,_details,_stages,_stage_runs}`, form sections in `workflows/form/*` (`_jira_fields`, `_task_fields`, `_runbook_fields`, `_images`), detail cards in `workflows/details/*` (`_jira`, `_task`, `_runbook`, `_pr_review`, `_log_time`) chosen by `WorkflowsHelper#workflow_details_partial`. Always nested under a project; only `development` and `runbook` are created here (`pr_review` comes from the Slack sync). Member actions are small guarded state transitions; Run stage (and Next in auto-run) enqueue `WorkflowSchedulerJob`. `show` also holds the full `StageRun` history — the only observability screen (no `StageRuns` controller). Helper: `WorkflowsHelper` (`stage_runnable?`, `current_stage_badge`, `runbook_copy_source_options`).
- Stages: `stages_controller.rb`; `app/views/stages/{new,edit,_form}`, form sections in `stages/form/*` (`_runbook_fields`, `_command_field`, `_prompt_fields`). Add/remove is runbook-only; editing is allowed on any stage. The form carries `data-controller="skill-insert template-fill"`: `template_fill_controller.js` previews the chosen prompt template into the prompt field. Helper: `StagesHelper` (`stage_run_mode_options`, `stage_template_options`).
- Syncs: `jira_syncs_controller.rb` / `bugsnag_syncs_controller.rb` with `app/views/{jira_syncs,bugsnag_syncs}/{new,edit,_form}`. CRUD for a project's syncs (listed on the project page) plus a `run` action that reports why a start was blocked.
- Prompt templates: `prompt_templates_controller.rb`; `app/views/prompt_templates/{index,show,new,edit,_form}`. The form lists `Prompts::Renderer::BUILT_IN_TOKENS` beside the body.
- Settings: `settings_controller.rb`; `app/views/settings/show.html.erb`. The one app-wide setting (agent CLI) goes through `AiCli::Runner`, not a model.
- Shared: `application_controller.rb`, `application_helper.rb` (lists skill directories under the project's `<local_directory>/.agents/skills`), `layouts/application.html.erb` (nav + flash), `shared/_skill_hints.html.erb` (clickable skill chips), `shared/_error_summary.html.erb` (validation error list, `record:` local, used by forms such as `stages/_form`). Concerns: `ProjectScoped`, `WorkflowScoped` (`set_workflow`; the including controller registers `before_action :set_workflow` after `ProjectScoped`), `ManualStartFlash` (maps an `AgentRuns::ManualStart` result to the redirect + flash for every "run now" action, included by `ProjectSlackSyncsController`, `ProjectBrainstormsController` and the sync controllers).
- Stimulus (auto-registered via `controllers/index.js`): `skill_insert_controller.js` (inserts `/skill-name` into the `data-skill-insert-target="input"` textarea), `template_fill_controller.js` (stage form template preview), `select_all_controller.js` (header checkbox toggles `data-select-all-target="row"` boxes on the project page).
- `app/views/pwa/`, `app/assets/` — Rails PWA defaults, images, stylesheets.

## Conventions

- These are plain Rails server-rendered CRUD controllers — no admin gem, no API-only mode, no JS framework beyond Turbo/Stimulus via importmap. Keep that: `create`/`update` re-render `:new`/`:edit` with `status: :unprocessable_entity` on failure, `destroy` redirects with a flash `notice`, forms are `form_with model:` partials shared between `new`/`edit`.
- Controllers nested under `/projects/:project_id` (workflows and the `Workflow*` action controllers, stages, jira/bugsnag syncs) `include ProjectScoped` (`app/controllers/concerns/project_scoped.rb`), which registers `before_action :set_project` first and 404s on an unknown project; don't redefine `set_project`. `ProjectsController`, `ProjectSlackSyncsController` and `ProjectBrainstormsController` use `params[:id]` and stay outside it.
- Controllers stay thin. State changes beyond CRUD (start, resume, advance, rollback, run) check preconditions and redirect with a flash `alert` when they don't hold, and do the work through model methods (`advance!`, `start_runbook!`, `resume_status`) or by calling a service's `blockers` / `start`. Don't put scheduler or agent logic in a controller, and don't run an agent or git command from a request.
- Enum-backed selects use the model's own keys (`PromptTemplate.stage_types.keys`, `Project.kinds.keys`, `Stage.run_modes.keys`) — never hardcode the value list in a view. Enum-dependent UI branches (`workflow.runbook?`, `project.personal?`) use the predicate methods.
- System-set fields are not editable from forms and not in strong params: `github_pr_url` (set by the implementation run, or by the Slack sync for review workflows), `status`, `kind` (the workflow controller derives it from a param limited to development/runbook), the agent run-tracking columns, `current_stage_id`. Don't add a field for them.
- Secrets (`uat_password`, `local_password`) are never rendered back into a form; a blank value means "keep".
- New "run now" actions `include ManualStartFlash` and finish with `redirect_after_manual_start` rather than hand-rolling flashes. New per-kind form or detail sections go in the existing `form/` or `details/` partial directories (and `workflow_details_partial` for details), not inline in `_form`/`_details`.
- Each user-facing action that triggers an agent run gives a flash explaining what happens next and where the result will show. Keep that wording tied to the real behaviour (e.g. results are imported by the next job tick).
- Test with RSpec, not scratch runners: add request/controller or model specs under `spec/` and run `RAILS_ENV=test bundle exec rspec`. Never run scratch scripts, `bin/rails runner` or console code against the development DB, and never click through a running dev server's destructive buttons (Delete, Start, Run) on real projects to "verify" a change.
