# ai-worker-orchestration

Scope: `app/jobs/**`, `app/services/**`, `config/sidekiq.yml`, `config/schedule.yml`, `config/initializers/sidekiq.rb`. Read `app/models/workflow.rb`, `stage.rb` and `project.rb` only for the public methods and enums this layer calls (`current_stage`, `effective_template`, `skill_list`, `advance!`, status/kind enums, project settings) — don't otherwise touch the model layer (`ai-worker-domain`) or the UI (`ai-worker-ui`). The overall design is in `docs/ARCHITECTURE.md` and `docs/RUNBOOK.md`; where they and the code disagree, the code wins.

## File map (the whole scope)

**Scheduling**
- `config/schedule.yml` — sidekiq-cron entries (loaded by `config/initializers/sidekiq.rb`): the scheduler runs on the `stage_execution` queue, more often in working hours than off-hours; the Jira, Slack-review and Bugsnag sync jobs and the hourly brainstorm job run on `default`. `config/sidekiq.yml` keeps concurrency at 1 on purpose (see Conventions).
- `app/jobs/workflow_scheduler_job.rb` — the tick. It walks **every** in-flight workflow (not one), in `position` order, in three phases:
  1. *Active workflows* — workflows that are implementing, reviewing or local-testing, plus `merged`/`uat_testing` ones whose agent is already running. Running agents are polled first so finished ones free their slot; then waiting workflows are started if (a) fewer than `MAX_CONCURRENT_AGENTS` (env, default 3) agents are running overall, (b) no agent is running in the same local clone (paths are normalised so different spellings of one clone count as one), and (c) the workflow is eligible: for development workflows only the first per project clone (earlier ones still waiting on review keep the slot); PR-review workflows are exempt from that head-of-line rule; runbooks only when `auto_run` is set or they were named via the job's `run_workflow_id` argument (the "Run stage" button).
  2. *Post-merge phase* — only when nothing is implementing/local-testing and no agent runs: confirm that `done` development workflows' PRs were merged (→ `merged`), then start one `merged` workflow's Jira update.
  3. *UAT phase* — workflows waiting for UAT whose scheduled time has passed (and failed-and-retrying UAT tests) are started whenever an agent slot is free; this phase does not wait for idle.
  One workflow's exception is logged and never stops the rest of the tick.
- `app/services/stage_executor.rb` — runs one workflow's current stage. `call` either **polls** (when `workflow.processing?`) or **starts** work by stage type; it never waits on the agent. Starting: implementation creates the branch then spawns the agent; pr_check inspects the PR (merged → `merged`; approved → `done`, unless checks fail or a local test failed, which count as changes requested; changes requested → merge main in, spawn a conflict-resolution run if needed, else the review-fix run; no decision → log and wait); task, jira_update, pr_review, uat_test, local_test and runbook_step each have their own start path. Finishing a run is per stage type and decides the next workflow status (e.g. implementation → `reviewing` or `local_testing`; Jira update → `jira_updated` or `uat_waiting`; runbook step → `waiting` for Next, or auto-advance). It also owns stale-run kill, the consecutive-failure cap that parks a workflow as `errored`, optional Slack review pings and auto-merge (both best-effort, never fail the stage), and the Playwright MCP wiring plus env-var credentials for UAT/local test runs. Every `Git::CommandError` / `Github::CommandError` / `AiCli::CommandError` / `ArgumentError` is caught in `call`, which logs a `failed` `StageRun` — never let one bubble up and crash the Sidekiq job.

**Agent CLI and prompts**
- `app/services/ai_cli/runner.rb` — the single place that launches the agent CLI (claude, cursor `agent`, or codex; the app-wide agent is read from Rails.cache, falling back to the `AGENT` env var). It is **not** blocking: `start` detaches the process, redirects output to a log file and returns its pid; `poll` is a non-blocking wait that returns `:running` or the exit status; `tail_new_lines` logs new log output across ticks. It also handles per-run options (allowed/disallowed tools, extra MCP config, env vars, model/effort).
- `app/services/ai_cli/output.rb` — parses the agent's final output for the marker lines stages rely on (`VAR:`, `JIRA_RESULT`, `UAT_RESULT`, `LOCAL_TEST_RESULT`, retest/feedback blocks, `POSTED`, fixed summary). `ai_cli/command_error.rb`, `git/command_error.rb`, `github/command_error.rb` — one error class per service.
- `app/services/prompts/stage_prompt.rb` — builds the final prompt text for a stage (stage prompt, else assigned/default template, else a built-in default; plus conflict prompt, Slack-message wrapper and review-fix additions). `app/services/prompts/renderer.rb` — the only place `{TOKEN}` placeholders and workflow variables are substituted.

**Git / GitHub**
- `app/services/git/branch_service.rb` — all git operations in the project's clone: create/resume a workflow's branch from fresh `main`, merge `main` into it (reporting conflicts), check out a remote branch, detect/abort an in-progress merge.
- `app/services/github/client.rb` — all `gh` calls: finding a PR, PR info, merged/review-decision/checks state, Actions run state, requesting review, enabling auto-merge, checking out fork PRs. PR *creation* is never done here — the agent does it during the implementation run, per its prompt.

**Detached-agent sync services** (same shape: a state directory under `tmp/` holding pid, start time, result file and log; `start` spawns an agent via `AiCli::Runner`; `running?`/`poll` read back the result file once the process ends and raise the module's own `FetchError` on a bad or missing result; `import` creates records idempotently; `blockers` lists why it can't run, on the fetcher or on its sync wrapper)
- `app/services/jira/agent_fetcher.rb` + `jira/ticket_sync.rb` — fetch a project's assigned Jira tickets through the agent's Atlassian MCP and create workflows for ones not yet imported. `app/jobs/jira_sync_job.rb` drives it.
- `app/services/slack/mention_fetcher.rb` + `slack/review_sync.rb` — fetch Slack mentions containing PR URLs (agent with a Slack-read-only tool allowlist) and create PR-review workflows (skipping closed, own or already-imported PRs). `app/jobs/slack_review_job.rb` drives it and enqueues the scheduler right after creating workflows.
- `app/services/slack/review_notifier.rb` — the one non-agent Slack integration: a direct Web API post (bot token) pinging reviewers. Optional and best-effort.
- `app/services/bugsnag/triager.rb` — agent run that files Jira Bugs for new Bugsnag errors and records them in the sync's ledger. `app/jobs/bugsnag_sync_job.rb` drives it (weekday, once per day for auto-sync ones).
- `app/services/brainstorm/planner.rb` + `app/jobs/brainstorm_job.rb` — goal-driven, read-only agent that proposes workflows for personal projects, only while the project has no pending workflow.
- Each sync job imports a finished result first, then starts a new run only if none is running and its own trigger rule holds (last fetch old enough for Jira/Slack, once per weekday after a set hour for Bugsnag, no pending workflow for brainstorm); fetch errors are logged and recorded on the sync/project as its "last result".
- `app/jobs/application_job.rb` — Rails default base class.

## Conventions

- **Never build a shell command as a `cd X && ...` string.** Subprocesses use `Open3.capture3(*command, chdir: dir)` (Git/Github services) or `Process.spawn(..., chdir:)` with an argument array (`AiCli::Runner`). Never interpolate untrusted text (ticket text, Slack text, PR titles) into a shell string — pass it as an argument or in the prompt/env.
- Each service raises its own `CommandError` subclass on a non-zero exit instead of returning a boolean. `StageExecutor` is the one place that turns these into a `failed` `StageRun`; the sync jobs rescue their own `FetchError` / `AiCli::CommandError`. Don't rescue inside the Git/Github/Runner objects.
- Agent runs are detached and polled across ticks; a job must never block on one. State that lets a later tick find the run lives on the workflow (`processing`, pid, log path, start time, log offset) or in the sync's `tmp/` directory. Everything that starts a run must record that state; everything that finishes one must clear it.
- Concurrency rules are the scheduler's contract: one running agent per local clone, at most `MAX_CONCURRENT_AGENTS` overall, development workflows of one project run strictly one after another. These checks aren't atomic, so the `stage_execution` queue must stay at Sidekiq concurrency 1 — parallelism comes from the detached agent processes. Don't relax a rule without revisiting the others.
- Every code path in `StageExecutor` that attempts work or reaches an outcome logs a `StageRun` whose `action` is in `StageRun::ACTIONS`. Add the new action to that constant (domain skill) *before* logging it — an unlisted action fails the model validation and turns into a crash or a bogus failure.
- A failed stage stays in its current workflow status so the next tick retries it; after `MAX_CONSECUTIVE_FAILURES` the workflow becomes `errored`, which the scheduler ignores until a person resumes it.
- Agents are given the least tool access that works (tool allowlists for the Slack, Bugsnag and brainstorm runs; denied `gh workflow run`/`gh api` for UAT/local tests). Secrets (UAT/local logins) reach the agent only as environment variables, never in prompts or logs; the Slack bot token is read from the environment by `Slack::ReviewNotifier` and never goes to an agent. Jira, Slack-read and Bugsnag access goes through the agent's own MCP connectors, so the app holds no tokens for them.
- Test with RSpec, not scratch runners. Put specs under `spec/services/**` or `spec/jobs/**` (stub `Open3`, `AiCli::Runner` and `Github::Client`, or use temp directories and temp git repos) and run `RAILS_ENV=test bundle exec rspec`. Never run scratch scripts, `bin/rails runner` or console code against the development DB, and never start a real agent against a real project to "try it".
